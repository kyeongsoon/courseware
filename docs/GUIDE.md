# 정보교과 코스웨어 개발 가이드라인

학생과 함께 수업에서 쓰는 코스웨어를 **작게 만들고, 수업에서 써 보고, 고치는** 순서로 진행하는 것을 권장합니다.

## 0단계. 먼저 결정할 것 (코딩 전)

| 항목 | 질문 | 이 저장소의 기본 선택 |
|---|---|---|
| 대상 | 몇 학년, 몇 반, 몇 명? 학생 기기는(크롬북/PC실/태블릿)? | 브라우저만 있으면 되는 웹앱 |
| 로그인 방식 | 학교 Google Workspace 계정이 있나? 없다면 이메일 가입? | Google + 이메일 둘 다 지원 |
| 학생 식별 | 무엇으로 학생을 구분하나? | 이름 + 학번(예: 30215) |
| 권한 | 교사/학생 외 역할이 필요한가? | `student`, `teacher` 2개 |
| 개인정보 | 수집 항목 최소화, 만 14세 미만 동의, 학교 정보보호 지침 | 이메일·이름·학번만 저장 |
| 기술 스택 | | Vite + React + Firebase (Auth, Firestore, Hosting) |

## 1단계. 기반 (지금 여기 ✅)

1. **① 로그인 – Firebase Authentication + Firestore** ← 이번 작업
   - Google / 이메일 로그인, 회원가입, 비밀번호 재설정
   - 첫 로그인 시 `users/{uid}` 프로필 문서 자동 생성 (역할 `student`)
   - 이름·학번 미입력 학생은 프로필 입력 페이지로 이동
   - 교사 권한은 Firebase 콘솔에서 `role: "teacher"`로 직접 변경
   - Firestore 보안 규칙으로 학생이 스스로 교사가 되는 것 차단
2. 배포 – Firebase Hosting (`npm run build && firebase deploy`)

## 2단계. 수업 구조

3. **학급(반) 관리** – 교사가 반을 만들고 참여 코드 발급 → 학생이 코드로 가입
   - `classes/{classId}` { name, teacherUid, joinCode }, `classes/{classId}/members/{uid}`
4. **단원/차시 콘텐츠** – 교사가 차시(제목, 설명, 자료 링크, 공개 여부)를 등록
   - `courses/{courseId}/lessons/{lessonId}`
5. **학생 대시보드** – 내 반의 공개된 차시 목록, 진도 표시

## 3단계. 정보 교과 핵심 활동

6. **퀴즈/형성평가** – 객관식·단답형, 자동 채점, 결과 저장 (`submissions`)
7. **코딩 실습** – 브라우저에서 Python 실행(Pyodide) 또는 블록코딩, 예제 입력·출력으로 자동 채점
8. **과제 제출** – 코드/파일 제출 (Cloud Storage), 교사 피드백

## 4단계. 교사용 도구

9. **실시간 수업 모드** – 교사가 현재 차시를 띄우면 학생 화면이 따라옴 (Firestore `onSnapshot`)
10. **결과 분석** – 문항별 정답률, 학생별 진도, CSV 내보내기
11. **(선택) AI 피드백** – 학생 코드에 대한 힌트 제공. 서버(Cloud Functions)에서만 API 키 사용

## 개발 원칙

- **기능마다 보안 규칙을 함께 작성** – 새 컬렉션을 만들면 `firestore.rules`에도 규칙 추가 (기본은 전부 차단)
- **비밀값은 저장소에 올리지 않기** – `.env.local`은 `.gitignore` 처리됨
- **에뮬레이터로 먼저 테스트** – `firebase emulators:start` 로 실제 학생 데이터와 분리
- **한 단계씩 수업에서 시범 운영** – 한 반에서 써 보고 학생 피드백 반영 후 확대
